# 如何使用本书

本书既是课程,也是运维参考。课程路径一次讲透一个概念;参考章节帮助你在日后诊断真实的域名问题。

## 本书面向谁

你可以在以下方面零经验起步:

- 域名注册
- DNS 管理
- HTML 或 CSS
- Linux 服务器
- TLS 证书
- 命令行工具

唯一需要的技能是:仔细阅读说明、保证能收到账户邮箱的邮件,以及在结果与预期不符时停下来。

## 学习方法

每个主要主题都遵循同一循环:

```text
理解 -> 规划 -> 变更 -> 观察 -> 验证 -> 记录 -> 继续
```

### 理解

弄清该组件做什么、不做什么。例如,DNS 负责定位服务器,但不会上传网站。

### 规划

在改动任何公开内容之前,写下目标值、当前值、预期效果和回滚方案。

### 变更

一次只做一个受控变更。避免同时修改 DNS、服务器配置和证书。

### 观察

阅读界面响应、命令输出、服务日志或 HTTP 状态。

### 验证

使用独立检查。"保存成功"的按钮提示,弱于一条返回预期记录的 DNS 查询。

### 记录

写清改了什么、何时改的、谁改的,以及如何验证的。

## 三种文本类型

### 讲解

讲解用于建立心智模型。即使没有讲解也能照抄命令,也应读完讲解。

### 操作步骤

操作步骤是编号动作。按顺序完成,并把你的结果与文中描述的信号对比。

### 参考

参考章节包含命令、记录格式、术语定义和决策树,不需要背下来。

## 示例值

本书使用虚构值:

```text
域名:        example.dpdns.org
Web 主机名:  www.example.dpdns.org
IPv4:        192.0.2.10
IPv6:        2001:db8::10
域名服务器:  ns1.dns-service.example
服务器用户:  user
```

文档专用地址和 `.example` 名称不是生产目标。只有当操作步骤明确要求使用你的真实值时才替换它们。

## 你的项目笔记本

在公开网站目录之外创建一个私有的 Markdown 文件,使用以下结构:

```markdown
# 网站项目笔记本

## 目标

## 域名

## 账户所有者

## 权威域名服务器

## DNS 记录

## 服务器

## 续期日期

## 变更记录

## 回滚备注
```

不要在笔记本里存放密码、API 密钥、恢复代码、Cookie 或私有证书密钥。

## 停止条件

出现以下情况时,停下来排查:

- 提交前显示的域名不是你想要的域名。
- 费用、名额消耗或政策与预期不符。
- 某条命令在无明确理由的情况下要求管理员权限。
- DNS 结果指向陌生地址。
- 证书包含错误的主机名。
- 删除、付款、注册或续期的结果含义不明。
- 页面指示要求你暴露凭据或绕过安全控制。

停下来是工作流的一部分,不是失败。

| 四周课程 | 每天学一两章并做练习 |
| 项目驱动 | 跟学第 0–3 部分,再按需回到参考章节 |

## 第一个练习

在你的笔记本中回答:

1. 你希望网站实现什么目标?
2. 谁负责域名续期?
3. 哪些信息绝不能出现在公开截图里?
4. 什么情况会让你在公开变更前停下来?
