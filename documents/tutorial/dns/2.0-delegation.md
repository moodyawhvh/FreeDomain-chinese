# 委派与外部域名服务器

本章是通用 DNS 章节,假设注册平台已获得外部权威域名服务器主机名。

## 同一域名的三个视角

### 注册视角

保存预期的权威域名服务器主机名。

### 父级 DNS 视角

发布解析器实际遵循的委派信息。

### 子级权威视角

发布该区域的 SOA、NS 以及常规资源记录。

三者必须足够一致,解析才能正常工作。

## 检查委派

```bash
dig NS example.dpdns.org
```

返回的域名服务器应与外部 DNS 服务分配的一组一致。

追踪解析路径:

```bash
dig +trace NS example.dpdns.org
```

追踪有助于区分父级委派问题与子区域问题。

## 直接检查子区域

```bash
dig @ns1.dns-service.example SOA example.dpdns.org
dig @ns1.dns-service.example NS example.dpdns.org
```

权威服务器必须先发布区域,等待缓存过期才有意义。

## 委派故障模式

| 现象 | 可能的故障层 |
| --- | --- |
| 父级仍指向旧的 NS 主机名 | 注册或父级委派 |
| NS 主机名正确但超时 | 外部权威服务或网络 |
| 一台域名服务器有应答,另一台没有 | 外部 DNS 同步或可用性 |
| SOA 显示区域不存在 | 外部 DNS 服务缺少该区域 |
| NS 正常但 A 记录为空 | 外部 DNS 区域缺少常规记录 |

## 不要混淆字段

```text
域名服务器字段:  ns1.dns-service.example
A 记录值:        192.0.2.10
CNAME 值:        another-host.example
解析器地址:      客户端上配置的某个 IP
```

每个值属于不同的上下文。
