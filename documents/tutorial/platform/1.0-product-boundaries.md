# DigitalPlat 做什么

理解产品边界可以避免最常见的配置错误:在注册控制面板里寻找网站或邮件记录。

## DigitalPlat 的职责

DigitalPlat 为受支持的名称提供注册控制层。根据当前界面和账户,它可能包括:

- 账户注册与登录
- 域名可用性检查与注册
- 特定命名空间的政策确认
- 外部权威域名服务器提交
- 域名状态与到期信息
- 续期流程
- 注册联系数据管理
- 产品通知与支持的账户功能

当前控制面板通知及其链接的政策是权威依据,因为可用性、限制、价格、暂停和各项要求都可能变化。

## 外部 DNS 的职责

外部权威 DNS 服务托管区域并提供域名服务器。用户在其界面中管理如下记录:

```text
A       IPv4 地址
AAAA    IPv6 地址
CNAME   主机名别名
MX      邮件路由
TXT     验证与邮件策略
CAA     证书颁发机构策略
SRV     服务发现
```

DigitalPlat 只保存用于委派的外部域名服务器主机名,不能替代外部 DNS 服务的记录编辑器。

## 网站托管的职责

Web 主机或服务器存放并运行网站。当 DNS 把主机名指向它之后,它才接受 HTTP 和 HTTPS 连接。

DigitalPlat 注册不包含:

- 上传 HTML 或应用代码
- 创建 Web 服务器
- 打开防火墙端口
- 配置反向代理
- 签发 HTTPS 证书
- 创建邮箱

这些是独立的通用网站任务,本书稍后覆盖。

## 完整关系

```text
DigitalPlat 注册
  |
  | 将域名委派到外部 NS 主机名
  v
外部权威 DNS
  |
  | 发布 A、CNAME、MX、TXT 等记录
  v
网站、邮箱及其他服务
```

## 示例

以 `example.dpdns.org` 为例:

1. DigitalPlat 记录该域名使用 `ns1.dns-service.example` 和 `ns2.dns-service.example`。
2. 外部 DNS 服务发布 `example.dpdns.org` 的区域。
3. 用户在外部服务中创建 `A` 记录。
4. 浏览器解析该记录并连接到 Web 服务器。

如果记录缺失,反复修改 DigitalPlat 的域名服务器字段并不会把它创建出来。

## 定位正确的故障层

| 症状 | 首先检查的位置 |
| --- | --- |
| 账户中看不到域名 | DigitalPlat Domain List |
| 委派的域名服务器不对 | DigitalPlat 域名的域名服务器设置 |
| NS 正确但缺少 `A` 记录 | 外部 DNS 区域 |
| DNS 正确但连接超时 | 服务器与防火墙 |
| HTTP 正常但 HTTPS 失败 | Web 服务器与证书流程 |
| 邮件无法路由 | 外部 DNS 的 MX 记录与邮件系统 |

## 读者练习

为每个任务写出归属:**DigitalPlat**、**外部 DNS** 或 **Web 服务器**:

1. 续期域名。
2. 添加 `www` 的 CNAME。
3. 上传 `index.html`。
4. 更换权威域名服务器。
5. 添加 MX 记录。
6. 配置 HTTP 重定向。

答案:DigitalPlat、外部 DNS、Web 服务器、DigitalPlat、外部 DNS、Web 服务器。
